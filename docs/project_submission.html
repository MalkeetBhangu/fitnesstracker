3. Architecture & Key Technical Decisions
1. Polymorphic Section Feed Model (Virtualization & Performance)

The Progress screen uses a Polymorphic Section Architecture (Section[]) managed via transformProgressToSections. Rather than rendering individual hardcoded scroll views, server/mock responses are decoupled and transformed into strongly typed discriminated union items:

  • CurrentWeightCard • GoalCard • WeightChartCard • BmiCard • RecentLogsCard • WalkthroughCard

This allows single-pass virtualization, recycling, smooth 60fps scrolling, and effortless addition/reordering of dashboard cards.

2. State Management & Zero-Latency Persistence (Zustand + MMKV)

User preferences (including selected language code) are managed through Zustand and paired directly with MMKV (react-native-mmkv) via Zustand's persist middleware. Unlike asynchronous AsyncStorage, MMKV offers synchronous C++ native bindings, eliminating UI flashes or race conditions during app rehydration.

3. Zero-Hardcoded-Strings Localization Pipeline (i18n)

Strict architectural rule enforced across the codebase: 100% of user-facing strings, units (kg, cm), months, and days reside in en.json and de.json. The custom getTexts(languageCode) selector provides type-safe reactive updates whenever a user toggles languages via the header options modal (...).

4. Custom SVG Graphics & Precision Visualizations

Interactive graphics are built from scratch using react-native-svg:

  • Interactive Weight Chart: Smooth cubic bezier curve with gradient fill, touchable active points, and dynamic speech bubble tooltip with notch pointer.
  • BMI Gauge: 4-band colored gauge (Underweight, Normal, Overweight, Obese) with dynamic geometric pin placement calculated directly from current BMI values.
5. Design Tokens & Responsive Dimensions

Centralized design token system in Colors.ts (strict RGBA color palette) and StyleHelper.ts (getHeight, getWidth) ensuring pixel-perfect fidelity across all iOS and Android device screen densities.
